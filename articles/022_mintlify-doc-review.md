## はじめに

AIにコードを書かせる機会が増えて、次は仕様書もお願いするようになりました。便利なんですが、レビューが完全に追いついていません。

Pull Requestが何件も並ぶと、正直言ってもう見ていられなくなるんですよね。差分を開くたびに、どこから手をつけるべきか悩む時間の方が長い気がします。

輪をかけて厄介なのが、AIが吐き出すMarkdownファイルそのものです。白黒の見た目で目が滑ってしまい、ドキュメント用のフォルダにファイルがずらっと並んでいるのを見ても、正直読む気が起きません。

そんな中で見つけたのが、Markdownを整ったWebページとして表示してくれる「Mintlify」というサービスです。導入するだけでレビューの負荷がぐっと下がったので、今回はその話を共有します📚

## Mintlifyを入れると何が変わるか

Mintlify は、もともとドキュメントサイトを自動で作るためのサービスです。Markdown で書いたファイルを渡すだけで、そのまま整った Web ページとして表示してくれます。

ドキュメント用のフォルダに Markdown ファイルを並べておくだけで、見出しやコードブロックがきれいにレイアウトされた状態で出てきます。導入の手間はほとんどありません。

これが思いのほか効きます。同じフォルダでも、エディタでファイル名がずらっと並んでいるのを見るのと、整形されたページとして表示されるのとでは、読み始めるまでの心理的なハードルがまるで違うんですよね。

中身は1文字も変えていないのに、開く気になるかどうかがまるで変わってきます。後回しにしていたドキュメントを、気づけば普通に開くようになっていました。

## なぜHTMLではなくMarkdownなのか

ここが今回いちばん言いたいところです。

最近は、AI に直接 HTML を出力させてドキュメントを作る、という話もよく聞きます。見た目まで一気に仕上がるので魅力的に見えるのですが、個人的にはあまりおすすめしません。

まず、生成のたびにデザインが変わってしまいます。AI が毎回違うレイアウトの HTML を吐き出すので、読む側は内容に入る前に、まず今回のレイアウトを読み解くところから始めることになります。見出しの付け方も強調の仕方もそのつど違うので、なかなか慣れません。

これでは、本来向き合うべき中身になかなかたどり着けません。ドキュメントを読む目的は内容を理解することであって、レイアウトを解読することではないはずです。

もう一つ、タグの分だけ入力も出力も長くなり、トークンを余計に消費します。`<div>` や `<span>` を書かせるだけで、AI にとっても読む側にとっても文字数が膨らんでいくわけです。ちりも積もればで、意外とばかにならないコストになります。

Markdown であれば、AI が触るのは文章の構造だけで済みます。見出しやリストといった骨組みさえ書けば、見た目は Mintlify 側が常に同じ形で与えてくれるので、デザインは毎回変わりません。

デザインが一定であれば、どこに何が書いてあるかを探し直す必要がなく、内容そのものに集中できます。前回読んだページと、同じ場所に同じように情報が並んでいる。この安心感は、思っている以上に大きいです。

この役割分担さえ成り立てば、道具は Mintlify でなくてもいいはずです。AI は構造を書くことに専念し、見た目は別のレイヤーに任せる。この線引きこそが、レビューの負荷をだいぶ軽くしてくれます。

## レビューの流れがどう変わったか

実際に、レビューのやり方そのものも変えました。Pull Request の差分を1行ずつ追いかける代わりに、ドキュメントを主軸に置くようにしています。

大事なところはドキュメントを読んで押さえ、細かい実装の妥当性は AI に任せる。差分をすべて自分の目で追うのをやめただけで、レビューにかかる時間はだいぶ減りました。

有料プランでは、ブランチごとにドキュメントのプレビューを作れます。Pull Request を出すタイミングでドキュメントも一緒に更新しておけば、そのブランチのプレビューを開くだけで変更の全体像がつかめる、という仕組みです。

コードの差分を延々と読むよりも、まとまった説明を1つ読むほうがずっと速いんですよね。実装の細かいところはどうせ AI が書いたものなので、そこは信頼して任せてしまうという判断です。

無料プランでも、ローカルでプレビューを起動することはできます。同じ Wi-Fi につながっていれば、パソコンで動かしたプレビューをスマホから見に行くこともできて、ちょっとした確認には十分です。

ブランチごとのプレビューはあくまで有料プランの機能なので、チーム全体で乗り換えるのはもう少し先になりそうです。とはいえ、選択肢の一つとして持っておく価値はあると思っています。

## おわりに

発表のあとの雑談で、参加者から「見やすくすることも大事だけど、それ以上にドキュメントを最新に保つ仕組みの方が大事ですよね」という指摘をもらいました。

まったくその通りだと思います。見た目を整えても、中身が古ければ意味がありません。ドキュメントをCI/CDで常に最新化する仕組みがあってはじめて、Mintlifyによる見やすさが生きてきます。

読みやすさと最新さ、この両方が揃ったときに、ドキュメントを主軸にしたレビューの進め方は完成するのだと思います😉
